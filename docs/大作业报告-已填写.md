## 1、作业内容

本次大作业完成的项目为“桃桃在线教育平台”，项目采用 Spring Cloud Alibaba 微服务架构进行设计与实现。系统围绕在线教育业务场景，构建了用户管理、课程管理、订单支付、学习记录、聊天互动、AI 推荐等多个业务模块，并通过网关、注册发现、配置管理、服务治理、分布式事务、消息队列和容器化部署等工程化能力，提高系统的可扩展性、可维护性和稳定性。

项目后端基于 Spring Boot 3.2 和 Spring Cloud Alibaba 2023 搭建，主要微服务包括 gateway-service、user-service、course-service、order-service、learning-service、chat-service 和 ai-service。前端基于 Vue 3、TypeScript、Vite 和 Element Plus 实现，通过统一网关访问后端接口。数据持久化采用 MySQL，缓存与会话状态采用 Redis，服务异步通信采用 RabbitMQ，服务注册发现与配置管理采用 Nacos，服务治理采用 Sentinel，分布式事务采用 Seata。项目已完成 Docker Compose 一键化部署，并进一步配置了 Nacos 三节点集群和 Nginx 统一入口，为后续扩展 Kubernetes 部署提供基础。

系统已实现的主要业务功能如下：

1. 用户体系：支持用户注册、登录、JWT 鉴权、用户信息维护、密码修改、角色区分等功能。
2. 课程体系：支持课程分类、课程列表、课程详情、讲师课程管理、章节课时管理、课程收藏、课程评价、问答等功能。
3. 订单与支付：支持课程订单创建、订单查询、模拟支付、订单取消、用户课程关联以及优惠券和秒杀优惠券功能。
4. 学习服务：支持学习记录、学习进度统计、学习报告和学习数据分析。
5. 聊天服务：支持课程聊天室、成员管理、消息发送、消息通知和 WebSocket 实时通信。
6. AI 服务：支持课程推荐、AI 聊天和基于学习行为的数据推荐接口。

这些模块之间不是单一服务内部的简单功能，而是通过 Gateway、OpenFeign、Nacos 服务发现、数据库事务和消息队列形成多个微服务协作的闭环流程。例如，订单创建时会调用课程服务完成课程学习人数更新；登录成功后用户 Token 会写入 Redis；课程学习数据会进入学习服务形成学习报告；聊天消息通过 MQ 和 WebSocket 完成异步处理与实时推送。

## 3、作业过程与分析

### 3.1 微服务架构设计

系统采用前后端分离和微服务架构。前端统一访问 Spring Cloud Gateway，网关根据路由规则将请求转发到对应的业务服务。后端服务按业务边界拆分，用户、课程、订单、学习、聊天和 AI 推荐分别由独立服务承载。服务之间通过 Nacos 进行注册与发现，通过 OpenFeign 实现远程调用，通过 Redis、RabbitMQ 和数据库保证业务流程的完整性。

在网关层，系统配置了用户服务、课程服务、订单服务、学习服务、聊天服务、AI 服务等路由规则，并实现了全局认证过滤器。对于登录、注册、课程列表和课程详情等公开接口配置白名单，其他接口需要携带 JWT Token。网关在认证通过后将用户 ID、用户名等信息写入请求头，传递给下游服务，从而实现统一认证和下游服务无状态化。

### 3.2 核心业务流程实现

用户模块实现了注册、登录、信息查询、信息修改、密码修改和退出登录。登录成功后系统生成 JWT Token，并将 Token 存储到 Redis 中，便于后续进行身份校验和会话控制。

课程模块实现了课程分类、课程列表、课程详情、教师课程管理、机构课程管理、课程问答、课程评价、课程收藏等功能。课程服务是系统的核心业务服务之一，既面向学员提供课程浏览和学习入口，也面向讲师和机构提供课程维护能力。

订单模块实现了课程订单创建、订单详情、订单列表、支付、取消订单、用户课程关联等功能。订单创建过程中会校验用户是否已购买课程，并在支付成功后建立用户与课程之间的购买关系。项目还实现了优惠券与秒杀优惠券功能，秒杀流程使用 Redis Lua 脚本进行库存扣减和一人一单校验，并通过消息队列异步发放优惠券，提高高并发场景下的系统稳定性。

学习模块记录用户学习进度，统计学习时长、完成率等数据，为学习报告和个性化推荐提供数据基础。聊天模块提供课程聊天室、成员管理、消息发送与通知功能，并通过 WebSocket 实现实时互动。AI 服务通过 Feign 调用课程服务和学习服务，结合用户学习数据提供课程推荐和智能问答能力。

### 3.3 Spring Cloud Alibaba 组件集成

项目使用 Nacos 作为服务注册发现中心。所有后端微服务均配置了 Nacos 地址，服务启动后可注册到 Nacos，网关和 Feign 调用可以通过服务名进行负载均衡访问。为了满足高可用要求，项目已将 Docker Compose 中的单节点 Nacos 改造为 nacos1、nacos2、nacos3 三节点集群，并增加 nacos-lb 作为统一入口。Nacos 集群数据使用 MySQL 中的 nacos_config 数据库进行持久化，避免配置和注册数据丢失。

项目使用 OpenFeign 实现服务间调用，例如订单服务通过 Feign 调用课程服务更新课程学习人数，AI 服务通过 Feign 调用课程服务和学习服务获取推荐所需数据。服务调用过程中结合 Spring Cloud LoadBalancer 实现负载均衡，并在部分 Feign 客户端中配置 fallback，提高调用失败时的容错能力。

项目使用 Sentinel 完成服务治理。用户登录、课程列表、课程详情、订单创建、订单详情、订单列表、AI 聊天等核心接口都接入了 SentinelResource 注解，并配置了 blockHandler 或降级处理方法。订单服务和 AI 服务还配置了慢调用比例熔断规则，能够在接口响应变慢或异常比例升高时触发降级，避免故障扩散。

项目使用 Seata 实现分布式事务。订单服务在 createOrderWithGlobalTx 方法上使用 GlobalTransactional 注解，订单创建时会调用课程服务更新课程学习人数。若远程调用失败或模拟异常发生，Seata 可以触发全局事务回滚，保证订单与课程统计数据的一致性。

项目当前异步通信使用 RabbitMQ 实现，主要用于聊天消息异步处理和秒杀优惠券发放。虽然大作业要求中指定 RocketMQ，但当前项目已具备消息队列异步解耦能力；后续如严格对齐课程要求，可将订单通知、秒杀发券或聊天通知场景迁移到 RocketMQ。

### 3.4 Docker 化部署与问题修复

项目已完成 Docker Compose 编排，能够一键启动 MySQL、Redis、RabbitMQ、Nacos、Sentinel、Seata 和多个后端微服务。为了保证容器内服务可访问，项目将原先写死的 localhost 和 127.0.0.1 配置改为环境变量，例如 MYSQL_HOST、REDIS_HOST、NACOS_ADDR、RABBITMQ_HOST、SEATA_SERVER_ADDR 等。这样既能支持本地直接运行，也能支持 Docker 网络内通过服务名访问。

在 Docker 化过程中，解决了多个实际工程问题：

1. 端口冲突问题：针对 3306、8091、8858 等端口占用，采用停止本机进程或调整容器端口的方式解决。
2. Nacos 启动问题：单节点模式下曾出现 No DataSource set，通过 Derby 模式修复；后续集群模式改为 MySQL 持久化。
3. 服务启动顺序问题：Nacos 未完全就绪时 gateway-service 和 ai-service 可能启动失败，因此为业务服务增加 restart: unless-stopped，提高容器自恢复能力。
4. 中文乱码问题：MySQL 初始化导入 SQL 时字符集曾被识别为 latin1，导致课程名称乱码。通过在 init.sql 中增加 SET NAMES utf8mb4，并在 MySQL 容器启动参数中设置 utf8mb4 字符集解决。
5. 前端请求问题：定位并解决了前端 Vite 服务未启动、PowerShell curl JSON 转义导致请求体非法等问题。
